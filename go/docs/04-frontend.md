# Frontend: templates, islands, admin, editor

Two separate frontends with opposite budgets.

- **Public**: server-rendered HTML, no framework, JS measured in kilobytes.
- **Admin**: server-rendered HTML from Go, plus one heavy bundle (Tiptap) loaded only
  on the two editor pages. Only the owner ever loads it, so its weight is irrelevant
  to SEO and to readers.

## Budgets (enforced by a CI check)

| Page | JS (brotli) | CSS (brotli) | Gate |
|---|---|---|---|
| Post page, initial | target 8 KB | target 10 KB | **fail above 15 KB JS** |
| Listing page, initial | target 6 KB | target 10 KB | fail above 12 KB JS |
| Admin, non-editor | target 10 KB | target 15 KB | fail above 25 KB JS |
| Admin, editor page | around 140 KB | | informational only |

For reference, the current post page is **196 KB brotli** of JS across 13 files.

## Public bundles

Three eagerly loaded bundles, split by page type, plus lazy chunks fetched on
interaction. No module graph, no import maps, no framework. Each file is hand-written
and self-contained.

```
core.js       every page      theme init, Track, ScrollDepth, RailToggle, BackToTop
post.js       /{slug}         CodeCopy, Toc, Lightbox, ReadingProgress, BookMode toggle
listing.js    listings        GridToggle, InfiniteListing

lazy, fetched on first use:
search.js     when the search overlay opens
comments.js   when comments scroll into view
subscribe.js  when the subscribe trigger is used
reader.js     when book mode is entered (the heavy 2-column overlay)
turnstile      third party, only when a comment form is opened
```

## The 23 islands

Each current `'use client'` component in `src/components/blog/` and its replacement.
Behaviour marked *(verify)* is inferred from the component name and needs confirming
against the source during M1.

| Component | Does | Replacement | Bundle |
|---|---|---|---|
| `Track` | Pageview beacon | `navigator.sendBeacon` on load | core |
| `ScrollDepth` | Max scroll depth + dwell sample on leave | scroll listener + `visibilitychange` beacon | core |
| `RailToggle` | Left sidebar rail open/closed | click handler + `localStorage` | core |
| `BackToTop` | Scroll-to-top button | ~15 lines | core |
| `RevealFallback` | Reveal-on-scroll fallback *(verify)* | `IntersectionObserver`, or drop if CSS `animation-timeline` covers it | core |
| `CodeCopy` | Copy button per code block | delegated click, `navigator.clipboard` | post |
| `Toc` | Highlights the active heading | `IntersectionObserver` over headings | post |
| `Lightbox` | Click an image to zoom | `<dialog>` element, native backdrop and Esc | post |
| `ReadingProgress` | Progress bar at the top | scroll listener, or pure CSS `scroll-timeline` where supported | post |
| `BookMode` | Toggle that enters book mode | click handler that dynamically imports `reader.js` | post |
| `BookReader` | Fullscreen 2-column reading overlay | the heavy one; stays lazy, rewritten vanilla | lazy |
| `GridToggle` | List vs grid on listings | class toggle + `localStorage` | listing |
| `InfiniteListing` | Infinite scroll pagination | `IntersectionObserver` + `fetch` of the next page's HTML fragment | listing |
| `SearchTrigger` | Opens the search overlay | inline, dynamically imports `search.js` | core |
| `SearchOverlay` | The overlay shell | `<dialog>` | lazy |
| `SearchClient` | Queries and renders results | `fetch` + template literals | lazy |
| `SubscribeTrigger` | Opens the subscribe overlay | inline | core |
| `SubscribeOverlay` | The overlay shell | `<dialog>` | lazy |
| `SubscribeForm` | Posts the email | plain `<form>` + `fetch` for the inline result | lazy |
| `Comments` | Renders the tree | server-rendered HTML fragment fetched on demand | lazy |
| `CommentsLazy` | Defers the above | `IntersectionObserver` | lazy |
| `CommentForm` | Submits a comment | plain `<form>` POST, enhanced with `fetch` | lazy |
| `Turnstile` | Cloudflare widget | third-party script, loaded with the comment form | lazy |

Note the pattern: several of these exist as separate components only because React
forces a component boundary for state. In vanilla, `SearchTrigger` + `SearchOverlay` +
`SearchClient` is one file, and so is the Subscribe trio.

Two are candidates for **removal rather than porting**: `ReadingProgress` and
`RevealFallback` may both be expressible in pure CSS on current browsers. Decide during
M1 with a measurement, not an assumption.

## Comments rendered on the server

Today the comment tree is fetched as JSON and rendered by React. In Quire 2.0 the
lazy fetch returns **rendered HTML** for the tree and the client inserts it. This
removes the client-side tree rebuild, the re-rooting of orphans and the tombstone
logic from the browser entirely, since it already exists on the server.

## CSS

Currently one 63 KB (raw) stylesheet covering public and admin, generated by Tailwind.

Plan: keep Tailwind for authoring (it is not a runtime cost), but emit **two**
stylesheets, `public.css` and `admin.css`, so a reader never downloads admin styles.
This is already a stated rule in `docs/performance.md` and is only partially honoured
today.

Route-specific CSS (`book.css`) stays route-specific.

## Fonts: fixing the actual LCP bottleneck

The current LCP bottleneck on `manhhung.me` is the Literata font at 107 KB. No amount
of Go changes that. It gets fixed here.

- Subset per script. A Vietnamese reader must not download Cyrillic or Greek ranges.
- Preload **only** the single face that renders the LCP element, not the family.
- `font-display: swap` with a metric-matched fallback so the swap does not shift layout.
- Target: under 30 KB for the preloaded face.

This is worth doing to the current Next site too, immediately, independent of the
rewrite. It is a half-day change with a larger user-visible effect than the entire
JavaScript reduction.

## Admin: server-rendered from Go

14 pages, all `templ`. Forms POST and redirect. JavaScript is added per page only
where a form round trip is genuinely wrong.

| Page | JS needed |
|---|---|
| Overview, Help, Log | none |
| Content, Trash, Comments, Newsletter subscribers | small: inline row actions, bulk select, confirm dialogs |
| Settings | small: live preview of theme and typography |
| Analytics | **none.** Charts render as server-generated SVG |
| Media | moderate: drag-and-drop upload, progress, multi-select |
| Editor, Page editor | the Tiptap bundle |

Analytics deserves emphasis: the current `AnalyticsView.tsx` plus
`AnalyticsPageDetail.tsx` are around 13 KB of React producing charts. Server-rendered
SVG produces the same charts with zero client JavaScript, and it is less code.

## Editor: Tiptap without React

`@tiptap/core` is framework agnostic. Only the `@tiptap/react` wrapper is dropped.

| Current | Lines | Port |
|---|---|---|
| `Editor.tsx` | 399 | `useEditor()` becomes `new Editor({element, extensions})`. Extension list unchanged |
| `EditorMenus.tsx` | 198 | Toolbar and bubble menu rewritten as DOM, roughly 250 lines |
| `CaptionedImage.tsx` | ~150 | React NodeView becomes a plain ProseMirror NodeView |
| `VideoNode` | ~100 | Same |

Everything else carries over untouched: StarterKit, Link, Underline, Table, TaskList,
TaskItem, Placeholder, `tiptap-markdown`, drag-and-drop image upload, the
Markdown/Review toggle, and the typewriter feedback.

Bundle effect: dropping `react-dom` (61 KB brotli) and the wrapper takes the editor
chunk from 177 KB brotli to roughly 140 KB.

### Editor features that must not regress

The earlier discussion established that the owner and other users write real posts in
this editor. These are not optional:

- **Autosave.** `localStorage` immediately, server every 5 seconds when dirty.
- **Crash recovery.** Reopening an editor with a newer local draft offers to restore it.
- **Conflict detection.** Save sends the version it loaded; a mismatch warns instead of
  overwriting.
- **Revision history.** Already exists (last 3 per slug). SQLite makes rows cheap;
  consider raising the limit, which is a product decision, not a technical one.
- **Vietnamese IME.** Composition events must be tested explicitly with Telex input.
  ProseMirror handles IME, but the toolbar and autosave must not interfere mid-composition.

## Building the JavaScript

`esbuild` has a Go API, so bundling is invoked from `go generate`, not from npm
scripts. Output is embedded with `go:embed`.

npm is still needed **once** to fetch Tiptap and its ProseMirror dependencies. To keep
`git clone && go build` working with no Node installed at all, the built
`assets/editor/editor.js` is **committed to the repository**.

Tradeoff: a generated artifact lives in git and must be regenerated deliberately when
the editor changes. Accepted, because the alternative is requiring Node to build a Go
project. CI verifies the committed bundle matches a fresh build so it cannot drift.

The hand-written public bundles (`core.js`, `post.js`, `listing.js`, and the lazy
chunks) have no dependencies at all and are minified by esbuild at build time.
